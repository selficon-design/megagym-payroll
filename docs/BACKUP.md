# Backup βάσης — MEGA GYM (Μισθοδοσία / HR + Ταμεία)

Οι δύο εφαρμογές χρησιμοποιούν **μία βάση** (Supabase). Το backup της βάσης καλύπτει λοιπόν και τις δύο.

## Τι υπάρχει

| Αντίγραφο | Πότε | Πόσο κρατιέται | Πού |
| --- | --- | --- | --- |
| **Ημερήσιο backup (δικό μας)** | Κάθε νύχτα ~03:15 | 90 ημέρες | GitHub → Actions → «Backup βάσης» → Artifacts |
| **Ημερήσιο backup Supabase (Pro)** | Κάθε μέρα | 7 ημέρες | Supabase → Database → Backups |
| **Μηνιαίο backup δηλώσεων** | Χειροκίνητα από τη ΓΔ | Όσο το φυλάξετε | Εφαρμογή HR → «Μηνιαίο backup» (ZIP με PDF) |

Το δικό μας ημερήσιο backup είναι αρχείο `MEGA_GYM_backup_ΕΕΕΕ-ΜΜ-ΗΗ.7z` και περιέχει:
- `1_schema.sql`: τη δομή της βάσης (πίνακες, συναρτήσεις, δικαιώματα)·
- `2_data.sql`: όλα τα δεδομένα, μαζί με συνημμένα, υπογραφές και παραστατικά (είναι αποθηκευμένα μέσα στη βάση).

Είναι κρυπτογραφημένο με **AES-256**, και κρυπτογραφημένα είναι και τα ονόματα των αρχείων μέσα του. **Ανοίγει μόνο με τον κωδικό backup.**

## Ρύθμιση (μία φορά)

1. GitHub → repo `megagym-payroll` → **Settings** → **Secrets and variables** → **Actions** → **New repository secret**.
2. Name: `BACKUP_PASSWORD` · Secret: ένας ισχυρός κωδικός, **τουλάχιστον 12 χαρακτήρες** (προτείνεται φράση 4–5 λέξεων με αριθμούς).
3. **Add secret**.
4. Φυλάξτε τον κωδικό σε ασφαλές σημείο, π.χ. σε διαχειριστή κωδικών ή σε χαρτί στο χρηματοκιβώτιο. Αν χαθεί, κανείς δεν μπορεί να ανοίξει τα αρχεία, ούτε το GitHub ούτε εμείς.
5. Δοκιμή: **Actions** → **Backup βάσης** → **Run workflow**. Σε λίγα λεπτά πρέπει να εμφανιστεί πράσινο ✓.

Χωρίς τον κωδικό, το backup σταματά με μήνυμα και **δεν ανεβαίνει κανένα αρχείο**. Το repo είναι δημόσιο, οπότε δεν ανεβαίνει ποτέ αρχείο χωρίς κρυπτογράφηση.

## Λήψη και άνοιγμα

1. GitHub → **Actions** → αριστερά **Backup βάσης** → η εκτέλεση της ημέρας που θέλετε.
2. Κάτω, στα **Artifacts**, πατήστε `MEGA_GYM_backup_…` για λήψη. Το GitHub το δίνει μέσα σε ένα .zip.
3. Ανοίξτε το .zip και μετά το `.7z` με το **7-Zip** (δωρεάν, 7-zip.org). Όταν ζητηθεί, δώστε τον κωδικό backup.

## Επαναφορά

Η επαναφορά αντικαθιστά δεδομένα. Γίνεται μόνο με απόφαση της ΓΔ, και πριν από αυτήν παίρνεται νέο backup της τρέχουσας κατάστασης.

- **Πρόβλημα των τελευταίων 7 ημερών:** Supabase → project `megagym-payroll` → **Database** → **Backups** → επιλογή ημέρας → **Restore**. Είναι ο πιο απλός τρόπος.
- **Παλιότερο ή μερικό** (π.χ. επαναφορά ενός πίνακα ή μιας ημέρας ταμείου): από το δικό μας αρχείο. Είναι τεχνική εργασία. Δίνετε το αρχείο και τον κωδικό στον τεχνικό (ή στο Claude), που:
  1. δημιουργεί μια **νέα, κενή** βάση δοκιμής και φορτώνει το `1_schema.sql` και μετά το `2_data.sql` (`psql -f …`)·
  2. βρίσκει εκεί τα στοιχεία που χάθηκαν·
  3. τα επαναφέρει στη ζωντανή βάση με νέα, ελεγμένη migration (ποτέ με αντικατάσταση όλης της βάσης).
